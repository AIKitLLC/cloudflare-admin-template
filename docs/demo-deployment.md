# Cloudflare demo deployment

Status (2026-10-23): no live demo URL has been verified. Track rollout in #40.
This guide uses the existing Payload/OpenNext application, not a static mockup.

## Deploy a separate instance

1. Use the README's **Deploy to Cloudflare** button after this change is merged.
   Select the intended Cloudflare account and a new Worker name, for example
   `aikit-admin-demo`. Let the deploy flow provision a separate [D1](https://developers.cloudflare.com/d1/) database and
   [R2](https://developers.cloudflare.com/r2/) bucket; do not select production resources. Verify the generated D1 ID
   replaces `DATABASE_ID` in the deployed copy.
2. Supply the inputs below. Keep the pinned pnpm version from `package.json`.
   Review the detected build/deploy commands: the existing `deploy` script runs
   Payload migrations and then the custom OpenNext Worker build/deploy.
3. Protect the admin and user [API](https://en.wikipedia.org/wiki/API) (application programming interface) paths with [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/policies/access/) as described in
   [admin-access.md](admin-access.md), including the alternate workers.dev hostname
   if it remains enabled. Use only synthetic data in the demo.
4. Create the first admin using the current [README](../README.md#first-admin-and-admin-access).
   Confirm the command targets the demo's remote D1 configuration, not local emulation.
   `main` supports both web first-run setup (#32) and the [CLI](https://en.wikipedia.org/wiki/Command-line_interface)
   (command-line interface) bootstrap.
5. Run the acceptance checks below and add the actual URL to the README only after
   they pass.

## Required inputs

| Name | Value |
| --- | --- |
| `PAYLOAD_SECRET` | Random Worker secret generated by the operator. |
| `JOBS_INTERNAL_SECRET` | A separate random Worker secret, at least 32 characters. |
| `PAYLOAD_PUBLIC_SERVER_URL` | The final [HTTPS](https://en.wikipedia.org/wiki/HTTPS) origin, without a path. Never use the example's localhost value in production. |
| `D1` | A new demo-only database bound under this exact name. |
| `R2` | A new demo-only bucket bound under this exact name. |

The deploy button discovers secrets from active entries in `.env.example`.
Descriptions in `package.json` explain them; descriptions alone do not declare secrets.
Set the final public origin before the first production request. If the generated
hostname is not known until provisioning, update the origin and redeploy before testing.

[Queues](https://developers.cloudflare.com/queues/) and [KV](https://developers.cloudflare.com/kv/) (key-value storage) are optional: keep their blocks commented unless the resources exist.
The existing cron runs every five minutes without a queue. Do not enable paid services
as an implicit part of this rollout.

## Acceptance checks

- The homepage loads over HTTPS; the admin login loads after Cloudflare Access.
- The first admin can sign in and open the permission matrix and job monitor.
- A limited demo account can read only the intended synthetic data and cannot change roles.
- A synthetic media upload and read exercise the demo R2 binding.
- A registered test job completes through the existing cron; logs show no missing
  secret, public-origin, migration, or binding errors.

Record the deployment commit, actual URL, date, and results in #40. Do not publish
a shared Super Admin password. A public read-only playground needs its own reviewed
permissions and is not provided by a normal admin deployment.
